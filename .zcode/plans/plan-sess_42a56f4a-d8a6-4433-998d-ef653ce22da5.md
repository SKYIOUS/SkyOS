## Goal

USB HID keyboard + mouse produce real input on SkyOS, feeding the **existing** `drivers::input` queues (consumed by `/dev/input/event0`/`event1` and tty) — same path PS/2 uses. Deliverable: boot in QEMU with `-device usb-kbd` / `-device usb-tablet` and get keystrokes + cursor into the GUI/shell.

## How input flows today (the contract to match)

- PS/2 mouse packet → `mouse.rs:feed_byte` → `input::push_mouse_button(0x110/0x111/0x112, …)`, `push_mouse_event(REL_X/REL_Y/REL_WHEEL, …)`, `sync_mouse()`. **Note:** PS/2 Y is positive-down at the push layer; GUI does `CURSOR_Y.sub(y_rel)`. HID boot-mouse Y is positive-up, so the USB bridge must **negate Y** before `push_mouse_event(REL_Y, …)`.
- PS/2 scancode → `tty.rs:feed_scancode` (via `pc_keyboard`) → `input::push_key_event(key_event.code as u16, pressed)`. The `code` is **`pc_keyboard::KeyCode as u16`**, not a Linux input code. The USB HID keyboard must emit the same `KeyCode` space.
- Queues: `KEYBOARD_EVENTS`/`MOUSE_EVENTS` (`ArrayQueue<InputEvent>`, cap 256), `InputEvent{kind:u16,code:u16,value:i32}` `repr(C)`, 8 bytes. devfs reads raw records.
- **No keycode constants exist** in the kernel — only `pc_keyboard::KeyCode`. I'll map HID usage IDs → `KeyCode` variants (stable across `pc_keyboard` versions, unlike literal discriminants).

## Concurrency / threading facts used

- Scheduler: `task::scheduler::spawn(extern "C" fn() -> !)` queues a kernel thread; it runs after `schedule()` (`main.rs:346`). Precedent: `spawn(run_async_tasks)` at `main.rs:332`.
- Preemption: LAPIC timer ~100 Hz → `try_schedule()`. A `spin_loop` thread is preempted; cooperation optional.
- Tick/sleep: `interrupts::get_ticks()` (100 Hz → 10 ms/tick). Min sleep = 1 tick ≈ 10 ms (HID full-speed 8 ms interval → at most one queued report, fine). Sleep = `take_current_thread()` + `status=Blocked` + `sleep_until=ticks+1` + `add_sleeping_thread` + `schedule()` (mirroring `sys_nanosleep`).
- Synchronization: `spin::Mutex` disables IRQs while held → safe to share a `static Mutex<XhciController>` between poller thread and any IRQ handler.
- DMA: `virt_to_phys_dma` (`memory/mod.rs:61`) = page-table walk, `unwrap`-or-panic. Any kernel-heap allocation has a valid controller-readable physical address. No special DMA pool needed; the existing `DmaBuf` pattern is correct. (UHCI's 32-bit-phys constraint is already handled by `as u32` cast there.)

## Plan — 8 tasks (build order = dependency order)

### Task 1 — Lift `XhciController` into a static (foundation for everything)

**Files:** `drivers/usb/mod.rs`, `drivers/usb/xhci.rs`

- In `mod.rs`: add `lazy_static! { pub static ref XHCI: Mutex<Option<XhciController>> = Mutex::new(None); }`. Populate it from `init()` instead of a local. Remove the now-dead `find_xhci_controller`/`init()` PCI scan (Task 7 finalizes this) — but keep `init()` as the entry that the boot path calls.
- `XhciController` holds raw pointers → `!Send`/`!Sync`. Add `unsafe impl Send for XhciController {}` / `unsafe impl Sync for XhciController {}` (justified: all mutation goes through the `Mutex`; raw addrs are MMIO/DMA buffers touched only under lock). Mirror how other DMA drivers in this tree are structured.
- Remove the controller being dropped at end of `init()`.

### Task 2 — Real XHCI Device Context + Transfer Rings (the core correctness fix)

**File:** `drivers/usb/xhci.rs`

Define the missing XHCI structures (none exist today — confirmed by grep):
- `XhciInputControlContext` (8 bytes add/ctrl bitmap + 56 reserved).
- `XhciSlotContext` (`#[repr(C, align(64))]`, 32 bytes: route string, speed, MTT, max exit latency, rhub port, #ports, parent slot, port count…).
- `XhciEndpointContext` (32 bytes: EP state via bits, mult, maxPStreams, LSA, interval, error count L23Hsy…, EP type, max packet size, max burst, dequeue ptr low/high, TR dequeue ptr, DCS, avg TRB len).
- `XhciDeviceContext` (slot + 31 endpoints, 2048 bytes, 64-aligned).
- `XhciTransferRing { trbs: [XhciTrb; N], enqueue: usize, cycle: u8 }` — N=256, page-aligned, with a Link TRB back to start for a true ring.

Replace the broken Address_Device (`xhci.rs:217-241`):
- Allocate a `Box<XhciDeviceContext>` (aligned), set `DCBAAP[slot] = phys` of it.
- Build Input Context: `A1=0x3` (slot ctx + EP0 ctx valid in add bitmap, control ctx bit 0 set), Slot Context with speed (from port reset speed), port number; Endpoint Context 0 = Control, `max_packet_size` (8/64 by speed), `error_count=3`, `dequeue_ptr = phys(ring) | DCS=1`, `avg_trb_len=8`.
- Issue `Address_Device` command with the input-context phys + slot id.
- Keep the per-device `XhciTransferRing` indexed by endpoint id (store a small `Vec<DeviceContext>` keyed by slot on `XhciController`, or a fixed `[Option<Box<DeviceContext>>; 256]`).

Replace `submit_transfer` (`xhci.rs:346-360`) to actually enqueue TRBs into the correct endpoint's ring (with cycle-bit handling + Link TRB), update the ring's enqueue pointer, write the ER/EP dequeue as needed, and ring the doorbell with the endpoint id. This makes `control_transfer` correct on real hardware (the trait method at `xhci.rs:467` already builds setup/data/status TRBs correctly — only the routing layer beneath it is wrong).

### Task 3 — `interrupt_transfer` (enables HID)

**File:** `drivers/usb/xhci.rs`

- Implement `UsbHostController::interrupt_transfer` (`xhci.rs:511`, currently `false`): allocate/configure the interrupt-IN endpoint's Transfer Ring (Endpoint Context with EP type = Interrupt-IN, `interval` from the endpoint descriptor, `max_packet_size` from descriptor), enqueue a Normal/IN TRB pointing at the report DMA buffer, ring the doorbell, `wait_for_event(32)` (Transfer Event), copy bytes back, return success. Reusable for both the one-shot enum path and the periodic poller.

### Task 4 — HID boot-protocol decode + usage→KeyCode table

**New file:** `drivers/usb/hid.rs` (add `pub mod hid;` to `mod.rs`)

- `set_boot_protocol(hcd, addr, iface)` — `SET_PROTOCOL(0)` + `SET_IDLE(infinite)` control transfers (USB HID class requests), so devices emit fixed-format boot reports.
- `decode_mouse_boot(report: &[u8])` → button changes / REL_X / REL_Y(negated) / REL_WHEEL, calling `drivers::input::push_mouse_*` + `sync_mouse()` (mirrors `mouse.rs`).
- `decode_keyboard_boot(report: &[u8], prev: &mut [u8;8])` → diff `keys[0..6]` vs prev → per-key `push_key_event(map_usage_to_keycode(u8), pressed)`; diff modifier byte → `push_key_event` for Ctrl/Shift/Alt/GUI left/right.
- `fn hid_usage_to_keycode(u: u8) -> Option<pc_keyboard::KeyCode>` — a `match` over HID usages 0x04–0xE7 → `pc_keyboard::KeyCode` variants (letters A–Z, digits, F-keys, navigation, modifiers, etc.). Returns `KeyCode`, caller does `as u16`. This is the single source of truth and survives `pc_keyboard` version bumps.

### Task 5 — Wire HID into `drivers::input`

**File:** `drivers/usb/xhci.rs` (and parallel for UHCI later)

- On HID interface found during enumeration: pick the interrupt-IN endpoint (address & 0x80, attributes & 0x03 == 3), record `{slot, ep_addr, max_packet, interval, kind: Keyboard|Mouse}` in a `static MUTEX<Vec<HidEndpoint>>` (or a field on the lifted controller).
- `set_boot_protocol` for the iface.
- The decoder functions (Task 4) are called from the poller (Task 6) per successfully polled report.

### Task 6 — USB HID poller kernel thread

**Files:** `drivers/usb/mod.rs`, `main.rs`

- `pub extern "C" fn usb_hid_poller() -> !` in `mod.rs`: loop { lock XHCI; for each registered HID endpoint: `interrupt_transfer(addr, ep, buf)`; on success `decode_*_boot(buf, &mut prev)`; drop lock; sleep 1 tick via `take_current_thread`+`sleep_until`+`add_sleeping_thread`+`schedule()`. } Never returns.
- `main.rs`: call `drivers::usb::init()` right after `pci::enumerate_pci()` (~line 266), and `task::scheduler::spawn(drivers::usb::usb_hid_poller)` next to the `run_async_tasks` spawn (~line 332). The poller runs only after `schedule()` at line 346, by which time LAPIC timer + input plumbing are live.

### Task 7 — Cleanup & latent-bug fixes

- Delete the duplicate PCI scan in `usb/mod.rs::find_xhci_controller`/`find_uhci_controller` — discovery is owned by `pci/mod.rs`. `usb::init()` becomes "ensure controllers are in the statics" (called once from main).
